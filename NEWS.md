# hovercraft 0.1.0

* `tip_on()` puts a tip on an HTML tag: plain text, or a named template filled from a record.
* `tip_define()` and `tip_template()` build and name templates, with `tip_title()`, `tip_text()`, `tip_badge()`,
  `tip_fields()` and `tip_code()` for the blocks. Placeholders are checked when the template is made.
* `tip_on()` looks inside the tag for something that can take keyboard focus before it warns, so the `div` Shiny puts
  around an input no longer gets a warning (#32).
* `tip_on()` gives an icon-only button, with no `aria-label` of its own, the words of a plain-text tip as its
  `aria-label`, so a screen reader has a name to read (#32). Engine 0.49.0 reads that name once: a tip that says the same as the tag's name is no longer also given as its description (#38).
* `tip_badge()` takes `status` (`"success"`, `"warning"`, `"danger"` or `"info"`; any other word is an error) in place
  of `tone`. The badge is coloured from the page's Bootstrap colours by a few lines of CSS that come with the engine's
  dependency (#32).
* `tip_table()` is an experimental spike that puts tips on the rows, cells and header cells of a `DT::datatable()` or `reactable::reactable()` table, drawn from each row's own values and following the data row through sorting, filtering and paging. Its shape may change (#36). Its `id` is a Shiny id, the same as `tip_on()`'s will be: one string with no whitespace, so `ns()` ids work, and every marked row, cell and header cell gets its own tip id derived from it (#41). The engine's kind of the tips is fixed (`table_row`, `table_cell`, `table_header`) and no longer set by `id`.
* `tip_table()` tips now show for the keyboard: the table gets one tab stop and the arrow keys, Home and End move between the rows, cells and header cells that have a tip (#39). The tips of a `reactable::reactable()` table are now described to screen readers, and a description no longer stays behind with the old row when `reactable` reuses its rows after a sort or a page change (#39). The help page lists what was checked in a browser (`DT` with `scrollX`, `scrollY`, `fixedHeader`, `colReorder`, `responsive` and server mode; `reactable` with selection, `groupBy` and `details`), what is not supported, and measurements for large tables (#39).
* `tip_spec()` (experimental) gives one `tip_table()` target its own settings, for now a `placement`: as `rows`, or as an entry of the named list given to `cells` or `headers`. A setting left as `NULL` is taken from `tip_table()`; a cell follows the table's placement, not its row's (#41).
* `tip_dependency()` gives the tip engine's script and CSS as an HTML dependency.
* `tip_theme()` and `tip_dependency(style = )` set how the tips look: roles for light and dark (fill, words, border, code
  background, corner, shadow, typeface), a `bslib::bs_theme()`, or CSS variables (through `tip_style(theme = )`). The tip follows `data-bs-theme`, so it turns
  dark with `bslib::input_dark_mode()`. Words below 4.5:1 on their fill give a `hovercraft_contrast` warning.
* The tip is now a shade of its page (Bootstrap's tertiary background with the page's text colour, in light and in dark), no longer the page inverted. A `bslib::bs_theme()` given to `tip_dependency(style = )` is read the same way, and the contrast check measures a role you leave out against that default. The bundled engine ships `tip.json` and its five preset files.
* `tip_style()` bundles a preset, a theme and a class for the tip box, and `tip_presets()` lists the presets (both experimental). `tip_on()` and `tip_dependency()` take it as `style =` (experimental on `tip_on()`), which also takes a preset name, `"none"`, or one part of a style: a `tip_theme()` or a `bslib::bs_theme()`. A tag's style beats the page's, and a value set nearer wins, value by value. A bare list, or a string with `:` or `;` such as `"color: red"`, stops with an error that says what `style` takes (#34, #42).
* `tip_dependency(theme = )` is now `tip_dependency(style = )`, with no old argument kept (#42).
* A page's theme is written on `body` and no longer on `:root`, so a page preset no longer overwrites it; the page's preset and class are written on the page as the engine's own attributes (#42).
* `tip_on(marker = )` (experimental) draws a visible cue on a tipped tag, off by default: `"underline"`, `"icon"`, `"corner"`, a bare tag as a custom icon, or a `tip_marker()`. `tip_marker(type, ..., line, icon)` (experimental) chooses the line of an underline (`"dotted"`, `"dashed"` or `"wavy"`, a long gentle wave in the text's own colour; left out, it follows the tip preset) or gives an icon, added as a hidden child. The markers are drawn by their own small CSS file, attached only when a marker is used. The pointer over a marked tag is the help cursor (a hand when the tip can be pinned), and a marker is in the tag's text colour so it keeps its contrast in light and dark.
* `tip_table(marker = )` and `tip_spec(marker = )` (experimental) draw a small corner triangle on the cells and header cells that have a tip, in `DT` and `reactable` tables, off by default. A `tip_spec()` marker beats the table's, and `"none"` takes it off one column. A row takes no marker, and `"underline"`, `"icon"` and an icon of your own stop with an error for now. The triangle is a background, so it takes no room and leaves the sort arrows of a `DT` table alone (#48).
* `tip_table(style = )` and `tip_spec(style = )` (experimental) give the tips of a table their look: a preset name, a `tip_style()`, a `tip_theme()` or a `bslib::bs_theme()`, as `tip_on(style = )` takes. The style of a `tip_spec()` beats the table's part by part, and a row's own style also reaches its cells that have none of their own (#50).
* `tip_on(placement = )` chooses the side a tip opens on (`"auto"`, `"top"`, `"bottom"`, `"left"` or `"right"`); left out, it is the page's choice, `"auto"` unless a tagged ancestor sets a side. `tip_on(id = )` gives the tip a Shiny id, the same rule as `tip_table(id = )`, so `ns()` works; it names the tip for `tip_show()`, `tip_hide()`, `tip_update()` and the hint input (#21, #50, #56).
* The bundled tip engine is now 0.50.0. It adds a hint event, calls to show, hide, pin and close a tip, short and long forms of a tip, motion and size settings, and a tip for a natively disabled control with a reason; only the calls to show and hide a tip, the hint event and the reason of a disabled control have an R side so far (#52, #56, #8).
* `tip_style()` (experimental) gains `motion` (`"fade"`, `"slide"` or `"none"`), `gap`, `max_width` and `pin_width`, checked against the ranges in the tip engine's contract and written on the page or on one tag like a theme; the nearest value wins, value by value, and a reader's reduced-motion setting always wins. There is no `delay`: the engine reads it only from the file of a preset (#54).
* Two vignettes, "Get started with hovercraft" and "Themes".
* The tip has a small arrow pointing at its tag, on by default and drawn when its fill is opaque (#31).
* `tip_theme(font = )` now sets the engine's own tip font variable, so a theme's font beats the font of a preset (#31).
* `tip_template()` stops with the "comes with a later version" error for a plain-list `group` or `host` block, or a block with the engine's new `parent`, `kicker` or `meta` fields, which have no R constructor yet; `tip_template_fields()` reads the title's new placeholders (#31).
* The bundled tip engine is now 0.51.0. It marks an element while its tip is open and can anchor a tip on the element's content (#58).
* `tip_table()` anchors the tip of every cell and header cell on its text, so a right-aligned number or header no longer gets a tip pointing at empty space. A row's tip still opens at the pointer. There is no argument for it (#58).
* A marked tag (`tip_on(marker = )`, `tip_table(marker = )`) is highlighted while its tip is open: a soft tint on the words, the icon's tag or the cell, a glow round a `bslib::value_box()`. There is no argument for it (#58).
* `tip_show()`, `tip_hide()` and `tip_update()` (experimental) open, close and change a tip from a Shiny server function, by the tip's `id` (the `id` given to `tip_on()`, the tag's own id, or a `tip_table()` tip id such as `<id>/row/3`). They take the module's namespace from `session`. `tip_hide()` closes a hint and never a pin. `tip_update()` rewrites `text`, `template`, `record` (which needs its `template` in the same call) or `placement`; an open tip draws its new words at once and a new placement is used the next time it opens (#56).
* `tip_on(events = )` (experimental) asks for a Shiny input: `"hint"` sends `input$<id>_hint`, a list of `state`, `text`, `by`, `via` and `reason`, each time the tip opens or closes. It is off unless asked for, since it sends a message on every hover. `"pin"` and `"copy"` are named but stop with an error until the pin inputs arrive (#56).
* The bundled tip engine is now 0.52.0. It adds a pin set by hand, a part mark, a class for the reason line and a `by` and `via` option on `pin()`; none has an R argument yet (#62).
* `tip_on(when_disabled = )` (experimental) gives a control that is switched off a reason: while it is disabled, its tip says "Not available:" and the reason, with a small lock before it, and when it is enabled again the reason goes and the control's own tip shows as usual. It works for a control disabled when the page is built and for one switched off later by the `update*(disabled = )` functions of Shiny, by script or by a disabled `fieldset`, on a Bootstrap 5 page and on the Bootstrap 3 page of a plain `fluidPage()`. The control is put in a small wrapper that is a tab stop only while the control is disabled, since a disabled control takes no keyboard focus and, under Bootstrap 5, no pointer: a button's wrapper has the role of a button and any other control's is a group named by its label. Focus moves to the wrapper when a focused control is switched off, and back when it is switched on. The wrapper takes the control's width and its place in a flex row; a control inside a `btn-group` or `input-group`, and a control disabled by `aria-disabled` alone, are not covered. `tip_on()` called again on the wrapper keeps one wrapper; a reason of blanks is an error, and a `marker` without a tip of its own is left off with a warning (#8).
